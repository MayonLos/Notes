## 直觉

学 C++ 基础，真正要建立的直觉只有一句：**你时刻在管理内存和生命周期，即使你没写 `new`。**

这是 C++ 和 Python/Java 最大的差别。别的语言里变量是「名字指向对象」，运行时负责回收；C++ 里变量**就是内存里的一块地**，出了作用域立刻消失，没人替你兜底。所以三个概念要一次分清：

| | 是什么 | 能否为空 | 能否改指向 |
|:---|:---|:---:|:---:|
| **值** | 一块内存，变量就是它 | — | — |
| **指针** | 存着别人地址的变量 | 能（`nullptr`）| 能 |
| **引用** | 另一个名字（别名） | 不能 | 不能 |

这张表能解释后面绝大多数选择：为什么传大对象用 `const&`（不拷贝、不能为空、语义清晰）、为什么容器里存指针要小心（谁负责删）、为什么悬垂指针是 UB（那块地已经不归你了）。

另一条贯穿始终的直觉是**类型在编译期就定死了**。模板之所以「零开销」，是因为编译器在编译期就为每个类型生成了一份代码，运行时没有任何类型判断。C++ 的性能承诺基本都来自这一点。

## 原理与推导

### 基本数据类型

| 类型 | 大小 | 范围 | 用途 |
|:---|:---|:---|:---|
| `bool` | 1 字节 | true/false | 布尔值 |
| `char` | 1 字节 | -128 ~ 127 | 单个字符 |
| `int` | 4 字节 | $-2^{31}$ ~ $2^{31}-1$ | 标准整数 |
| `long long` | 8 字节 | $-2^{63}$ ~ $2^{63}-1$ | 极大整数 |
| `float` | 4 字节 | $\pm 3.4 \times 10^{\pm 38}$ | 单精度浮点 |
| `double` | 8 字节 | $\pm 1.7 \times 10^{\pm 308}$ | 双精度浮点 |

> 负数的底层表示是补码，范围不对称的原因见 [[原码反码补码]]。

**常用修饰符**：`unsigned`（无符号）、`const`（不可修改）、`static`（改变作用域和存储期）。

### 变量与初始化

```cpp
int x = 10;         // 传统初始化
int y{5};           // 列表初始化（推荐，C++11+）
int z{};            // 零初始化

static int counter = 0;   // 静态变量：程序整个生命周期存在
```

> [!tip] 优先用列表初始化 `{}`
> 它会**阻止窄化转换**：`int x{3.14}` 直接编译报错，而 `int x = 3.14` 会静默截断成 3。

### 指针

```cpp
int value = 42;
int* ptr = &value;     // & 取地址

std::cout << *ptr;     // * 解引用，输出 42
ptr->member;           // 等价于 (*ptr).member

int arr[5] = {1,2,3,4,5};
int* p = arr;          // 数组名退化为指针
```

### 引用

引用是别名，**必须初始化，且创建后不能改指向**：

```cpp
int value = 42;
int& ref = value;
ref = 100;        // 修改的是 value，value 变成 100
```

### 函数参数传递

```cpp
void byValue(int x)              { x++; }   // 值传递：复制，不影响原变量
void byRef(int& x)               { x++; }   // 引用传递：修改原变量
void byConstRef(const std::string& s) { }   // 常量引用：高效传大对象，不修改

int power(int base, int exp = 2);           // 默认参数
```

> [!important] 选择规则
> - 小类型（`int`、`double`、指针）→ **值传递**，拷贝比间接寻址还便宜
> - 大对象只读 → **`const&`**
> - 需要修改调用方的变量 → **`&`**

**函数重载**：同一作用域内名称相同、**参数列表不同**（返回类型不算）：

```cpp
int add(int a, int b);
double add(double a, double b);
```

### 数组与字符串

```cpp
int arr[] = {1, 2, 3};    // 自动推断长度 = 3

std::string s = "Hello";  // 推荐：自动管理内存
s += " World";
s.length();               // 11
```

### 控制流

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
for (int num : v) { std::cout << num; }   // 范围 for（推荐）
for (int i = 0; i < 5; ++i) { }           // 传统 for
```

### 模板入门

```cpp
template<typename T>
T max_value(T a, T b) { return (a > b) ? a : b; }

max_value(5, 3);      // T 推导为 int
max_value(5.5, 3.2);  // T 推导为 double
```

编译器为每个用到的 `T` **单独生成一份代码**（实例化）——所以模板是零运行时开销的，代价是编译时间和代码体积。

## 例题

### 例 1 · 指针 vs 引用，什么时候用哪个

```cpp
// 需要「可能没有」的语义 → 指针
Node* find(int key);              // 找不到返回 nullptr

// 一定存在，只是不想拷贝 → 引用
void print(const std::string& s); // s 一定有效
```

**判据**：能不能为空。能为空用指针，不能为空用引用。这条能决掉九成的选择。

### 例 2 · 值传递为什么改不了原变量

```cpp
void increment(int x) { x++; }    // x 是副本
int a = 5;
increment(a);
// a 仍然是 5
```

`x` 是 `a` 的**拷贝**，函数里改的是拷贝。要改原值必须写 `int& x`，让 `x` 成为 `a` 的别名。

### 例 3 · 悬垂指针的产生

```cpp
int* makeBad() {
    int local = 42;
    return &local;     // local 出作用域即销毁
}                      // 返回的地址已经无效
```

栈上的 `local` 在函数返回时就没了，指针指向的那块内存不再属于你。读它是**未定义行为**——可能读到旧值，可能崩溃，可能一切正常直到某天出问题。这类 bug 的解法见 [[内存管理]]。

## 易错点

> [!warning] 悬垂指针（Dangling Pointer）
> 指向已释放内存的指针，解引用是 UB。删除后立刻置空：
> ```cpp
> delete ptr;
> ptr = nullptr;    // 防止二次释放和误用
> ```
> 更好的做法是根本不用裸 `new/delete`——见 [[内存管理]]。

> [!warning] `=` 与 `==` 写混
> `if (x = 5)` 是**赋值**，结果永远为真。养成把常量写左边（`if (5 == x)`）或开启编译警告的习惯。

> [!warning] 数组越界不报错
> C++ **不做边界检查**。`arr[10]` 在长度为 5 的数组上不会抛异常，而是**未定义行为（UB）**——不要理解成「安静地读写别人的内存」这种确定后果：编译器可以假设越界不会发生，据此做出的优化能让程序表现得毫无道理（循环被删掉、检查被优化没）。可能崩、可能读到垃圾、也可能看似正常直到换个编译选项就变样。用 `std::vector` 的 `.at()` 或范围 for 规避。

> [!warning] 有符号/无符号混用
> ```cpp
> for (int i = 0; i < v.size(); ++i)   // v.size() 是 unsigned
> ```
> 比较时 `int` 会被提升为 `unsigned`，`-1` 变成一个巨大的正数。用 `size_t` 或范围 for。

> [!warning] C 风格字符串的缓冲区溢出
> `char[]` + `strcpy` 不检查长度。优先用 `std::string`，它自己管理内存和长度。

> [!warning] 局部变量返回引用/指针
> 见例 3。返回栈上对象的地址或引用，函数一返回就失效。要么返回值（有 RVO 优化，不慢），要么返回堆上对象的智能指针。
