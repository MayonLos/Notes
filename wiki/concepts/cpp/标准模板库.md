> **一句话定义**：C++ 标准库的核心，由**容器、迭代器、算法**三部分组成——容器存数据，算法处理数据，迭代器把两者解耦。

## 直觉

STL 最值得理解的不是有哪些容器，而是**它为什么这么设计**。

假设有 $M$ 种容器和 $N$ 种算法。如果每种算法都要为每种容器写一遍，就要写 $M\times N$ 份代码。STL 在中间插了一层**迭代器**：算法只跟迭代器打交道，容器只负责提供迭代器。于是代码量降到 $M+N$。

```
容器 ──提供──> 迭代器 <──使用── 算法
```

这就是为什么 `std::sort(v.begin(), v.end())` 里没有 `v` 本身——**算法根本不知道自己在排一个 vector**。

第二个核心直觉是**容器选型只看两件事：内存布局和复杂度**。

| 布局 | 代表 | 强项 | 弱项 |
|:---|:---|:---|:---|
| 连续内存 | `vector` | 随机访问、缓存友好 | 中间插入 |
| 链式节点 | `list` | 任意位置插删 | 随机访问、缓存差 |
| 平衡树 | `map`/`set` | 有序 + $O(\log n)$ | 常数较大 |
| 哈希表 | `unordered_map` | 平均 $O(1)$ | 无序、最坏 $O(n)$ |

实践中的默认答案是 **`vector`**。它的 $O(n)$ 中间插入在现代 CPU 上常常比 `list` 的 $O(1)$ 还快——因为连续内存对缓存友好，而链表每跳一个节点就是一次潜在的 cache miss。**复杂度不等于性能**，这是 STL 教给人的最反直觉的一课。

## 原理与推导

### 三大支柱

| 组件 | 作用 | 示例 |
|:---|:---|:---|
| **容器** | 存储数据的数据结构 | `vector`、`map`、`set` |
| **迭代器** | 类指针对象，统一遍历接口 | `begin()`、`end()` |
| **算法** | 通用操作，作用于迭代器区间 | `sort`、`find`、`transform` |

### 序列容器

**`vector` — 动态数组（默认选择）**

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
v.push_back(6);      // 末尾添加，均摊 O(1)
v.pop_back();        // 删除末尾 O(1)
v[0];                // 随机访问 O(1)
v.size();
```

连续内存、随机访问快、缓存友好；中间插入 $O(n)$。

**`list` — 双向链表**

```cpp
std::list<int> lst = {1, 2, 3};
lst.push_front(0);   // O(1)
lst.remove(3);
lst.sort();          // 成员函数版本，不能用 std::sort
```

任意位置插删 $O(1)$（前提是已有迭代器），**无随机访问**。

**`deque` — 双端队列**

```cpp
std::deque<int> dq;
dq.push_front(0);    // O(1)
dq.push_back(4);     // O(1)
```

两端 $O(1)$、也支持随机访问，但内存**分段**不连续。

### 关联容器

**`set` / `map` — 有序（红黑树，$O(\log n)$）**

```cpp
std::set<int> s = {3, 1, 4, 1, 5};   // 自动排序去重 → {1, 3, 4, 5}
s.insert(2);
s.find(3);

std::map<std::string, int> age;
age["Alice"] = 25;
for (const auto& [name, years] : age) {   // C++17 结构化绑定
    std::cout << name << ": " << years;
}
```

**`unordered_map` / `unordered_set` — 哈希表（均摊 $O(1)$）**

```cpp
std::unordered_map<std::string, int> dict;
dict["key"] = 100;
```

### 容器选择表

| 容器 | 访问 | 插入/删除 | 有序 | 适用场景 |
|:---|:---|:---|:---:|:---|
| `vector` | $O(1)$ | $O(n)$ | ❌ | **默认选择**，频繁随机访问 |
| `list` | $O(n)$ | $O(1)$ | ❌ | 频繁中间插删且已有迭代器 |
| `deque` | $O(1)$ | 两端 $O(1)$ | ❌ | 需要双端操作 |
| `set` | $O(\log n)$ | $O(\log n)$ | ✅ | 唯一 + 有序 |
| `map` | $O(\log n)$ | $O(\log n)$ | ✅ | 键值对 + 有序 |
| `unordered_map` | 均摊 $O(1)$ | 均摊 $O(1)$ | ❌ | 键值对，只查不排 |

### 迭代器

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};

auto it = v.begin();   // 指向第一个元素
std::cout << *it;      // 1
++it;

auto rit = v.rbegin(); // 反向迭代器，指向最后一个
std::cout << *rit;     // 5

for (int val : v) { }  // 范围 for，底层就是迭代器
```

> [!important] `end()` 指向「最后一个元素之后」
> 它不是最后一个元素，**不能解引用**。区间是左闭右开 $[begin, end)$，所以 `end() - begin()` 正好等于元素个数。

### 常用算法

```cpp
#include <algorithm>
std::vector<int> v = {3, 1, 4, 1, 5, 9, 2, 6};

std::sort(v.begin(), v.end());                        // 升序
std::sort(v.begin(), v.end(), std::greater<int>());   // 降序

auto it = std::find(v.begin(), v.end(), 4);
int cnt = std::count(v.begin(), v.end(), 1);

std::vector<int> sq(v.size());
std::transform(v.begin(), v.end(), sq.begin(),
    [](int x) { return x * x; });
```

## 例题

### 例 1 · 容器选型的实际判断

需求：存 10 万条记录，按 ID 查询，偶尔插入，不需要顺序。

- `vector` + 线性查找 → 查询 $O(n)$，太慢
- `map` → 查询 $O(\log n)$，有序但用不上
- **`unordered_map` → 均摊 $O(1)$，正解**

如果改成「需要按 ID 顺序遍历输出」，答案就变回 `map`——**选型永远由访问模式决定，不是由「哪个更高级」决定。**

### 例 2 · 删除元素的正确写法（erase-remove）

```cpp
// 错误：remove 只是把元素移到后面，不改变 size
std::remove(v.begin(), v.end(), 3);

// 正确：remove 返回新逻辑末尾，再用 erase 真正删除
v.erase(std::remove(v.begin(), v.end(), 3), v.end());
```

原因是**算法只看迭代器，看不见容器**——它没有权限改变容器大小，只能重排元素并告诉你新边界。这正好印证了迭代器解耦的设计。

（C++20 起可以直接写 `std::erase(v, 3)`。）

### 例 3 · 遍历中删除

```cpp
// 错误：erase 后 it 失效
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it == 3) v.erase(it);

// 正确：erase 返回下一个有效迭代器
for (auto it = v.begin(); it != v.end(); )
    if (*it == 3) it = v.erase(it);
    else          ++it;
```

## 易错点

> [!warning] 迭代器失效
> - `vector::push_back` 触发扩容 → **所有**迭代器、指针、引用失效
> - `vector::erase` → 删除点及其之后的迭代器失效
> - `map`/`set::erase` → 只有被删元素的迭代器失效，其余仍有效
>
> 在遍历中修改容器前，先确认这条容器的失效规则。

> [!warning] `[]` 会静默插入
> `map` 的 `operator[]` 在键不存在时**创建一个默认值元素**。只是想查询请用 `.find()` 或 `.at()`，否则查一次就多一条数据。

> [!warning] 用 `std::sort` 排 `list`
> `std::sort` 要求**随机访问迭代器**，`list` 只有双向迭代器，编译直接报一大堆模板错误。`list` 要用成员函数 `lst.sort()`。

> [!warning] 混淆 `size()` 和 `capacity()`
> `size()` 是实际元素个数，`capacity()` 是已分配空间。`reserve()` 只改 capacity（避免反复扩容），`resize()` 才改 size（真的加元素）。

> [!warning] 拿复杂度当性能
> `list` 中间插入 $O(1)$、`vector` 是 $O(n)$，但实测中 `vector` 常常更快——连续内存对缓存友好。**默认用 `vector`，只有实测证明是瓶颈时才换。**

> [!warning] 遍历时用 `auto` 而不是 `const auto&`
> ```cpp
> for (auto s : bigStrings)        // 每次循环拷贝一个 string
> for (const auto& s : bigStrings) // 不拷贝
> ```
> 大对象容器上这个差别是数量级的。
