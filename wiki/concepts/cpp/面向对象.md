> **一句话定义**：以对象为中心的编程范式，四大原则是抽象、封装、继承、多态，用来管住大规模程序的复杂度。

> **后续**：→ [[标准模板库]]（泛型设计）→ [[内存管理]]（RAII 是 OOP 的杀手级应用）

## 直觉

OOP 的四个词里，**封装是目的，其余三个是手段**。

封装解决的问题是：一个程序大到一定程度，任何人都无法记住所有细节。把状态藏起来、只暴露接口，别人就只需要理解接口。`private` 不是防坏人，是**减少你必须同时想的事情的数量**。

C++ 的 OOP 有一个和 Java/Python 都不同的关键点：**对象有确定的生命周期，析构函数一定会被调用**。这看起来是个小细节，实际上是 C++ 最强的特性——因为它让「资源释放」可以绑定到「对象销毁」上，而对象销毁是编译器保证的，异常也不例外。这就是 RAII（[[内存管理]]），C++ 里几乎所有资源管理都靠它。

多态的直觉则是**把「用什么」和「怎么做」分开**。调用方只认识 `Shape`，不关心它是圆还是方；加一种新形状不用改调用方一行代码。代价是一次指针间接（虚表查找），几乎可以忽略。

所以本页可以这样读：封装划边界 → 继承建层次 → 虚函数把「选哪个实现」推迟到运行时 → 析构函数保证收尾。

## 原理与推导

### 四大原则

| 原则 | 含义 |
|:---|:---|
| **抽象** | 隐藏实现细节，只暴露本质特征 |
| **封装** | 隐藏内部状态，提供公共接口 |
| **继承** | 代码复用，建立类层次 |
| **多态** | 统一接口，多样实现 |

### 类与访问控制

```cpp
class Animal {
public:
    std::string name;
    void eat() { std::cout << name << " 在吃\n"; }
protected:
    int age;        // 子类可访问，外部不可
private:
    int energy;     // 仅类内可访问
};
```

| 修饰符 | 类内 | 派生类 | 类外 |
|:---|:---:|:---:|:---:|
| `public` | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ❌ |
| `private` | ✅ | ❌ | ❌ |

### 构造函数与析构函数

```cpp
class Person {
    std::string name;
    int age;
public:
    Person() : name("未知"), age(0) {}                        // 默认构造
    Person(const std::string& n, int a) : name(n), age(a) {}  // 参数化构造
    ~Person() { std::cout << "Person " << name << " 销毁\n"; }
};
```

> [!important] 初始化列表优于函数体内赋值
> `: name(n)` 是**初始化**（直接构造），函数体里 `name = n` 是**先默认构造再赋值**，多一次操作。`const` 成员和引用成员**只能**用初始化列表。

### 继承与虚函数

```cpp
class Vehicle {
public:
    virtual void start() { std::cout << "车启动\n"; }
    virtual ~Vehicle() {}    // 基类析构函数必须为虚函数
};

class Car : public Vehicle {
public:
    void start() override {  // override 让编译器帮你检查
        std::cout << "汽车引擎启动\n";
    }
};
```

**虚函数机制**：编译期为每个含虚函数的类建一张**虚表（vtable）**，对象里存一个指向它的 `vptr`。运行期通过 `vptr` 查表调用实际函数——开销是一次指针间接，代价极小但**无法内联**。

```cpp
void test(Vehicle& v) { v.start(); }   // 运行时按实际类型分派
Car car;
test(car);        // 输出「汽车引擎启动」
```

### 抽象类与接口

```cpp
class Shape {
public:
    virtual void draw() = 0;             // 纯虚函数
    virtual double area() const = 0;
    virtual ~Shape() {}
};

class Circle : public Shape {
    double radius;
public:
    void draw() override { std::cout << "画圆\n"; }
    double area() const override { return 3.14159 * radius * radius; }
};

// Shape s;   // 错误：抽象类不能实例化
Circle c;     // 正确
```

含纯虚函数的类**不能实例化**，只能作为接口被继承。

### 运算符重载

```cpp
class Vector2D {
    double x, y;
public:
    Vector2D operator+(const Vector2D& o) const {
        return Vector2D(x + o.x, y + o.y);
    }
    bool operator==(const Vector2D& o) const {
        return x == o.x && y == o.y;
    }
};
```

## 例题

### 例 1 · 为什么基类析构函数必须是虚的

```cpp
class Base { public: ~Base() {} };                 // 非虚！
class Derived : public Base { int* data; public: ~Derived() { delete[] data; } };

Base* p = new Derived();
delete p;      // 只调用 ~Base()，~Derived() 不执行 → data 泄漏
```

改成 `virtual ~Base() {}` 后，`delete p` 会先调 `~Derived()` 再调 `~Base()`。

**规则**：**任何打算被继承的类，析构函数都要是 virtual**。反过来，不打算被继承就用 `final`。

### 例 2 · 初始化列表的执行顺序陷阱

```cpp
class Bad {
    int b;
    int a;
public:
    Bad() : a(1), b(a) {}   // 看起来 a 先初始化？
};
```

实际执行顺序按**成员声明顺序**：先 `b`，后 `a`。所以 `b(a)` 用到的是**还未初始化的 `a`**——未定义行为。

**规则**：让初始化列表的书写顺序和声明顺序保持一致，编译器警告（`-Wreorder`）能帮你发现。

### 例 3 · 多态如何消除 switch

不用多态：

```cpp
switch (shape.type) {
    case CIRCLE: drawCircle(shape); break;
    case SQUARE: drawSquare(shape); break;
    // 每加一种形状，所有 switch 都要改
}
```

用多态：

```cpp
for (auto& s : shapes) s->draw();   // 加新形状不用动这里一个字
```

这就是「开闭原则」——**对扩展开放，对修改封闭**。

## 易错点

> [!warning] 基类析构函数不是虚的
> 见例 1。通过基类指针 `delete` 派生类对象，派生类的析构函数不会执行，资源泄漏。**这是 C++ OOP 第一大坑。**

> [!warning] 初始化列表顺序 ≠ 书写顺序
> 执行顺序永远是**成员声明顺序**。见例 2。

> [!warning] 对象切片（Object Slicing）
> ```cpp
> void f(Base b);        // 值传递！
> f(derivedObj);         // 派生类部分被「切掉」，多态失效
> ```
> 多态**必须**通过指针或引用（`Base&` / `Base*`），值传递会退化成基类对象。

> [!warning] 在构造/析构函数里调用虚函数
> 构造期间派生类部分还没建好，虚表指向的是**当前正在构造的这一层**，调用虚函数不会分派到派生类。析构时同理。想要多态行为，得等对象构造完成之后。

> [!warning] `override` 不写，静默变成重载
> 参数或 `const` 写错一点，就不是覆盖虚函数而是新增一个重载函数，调用时永远走不到你的实现，而且**不报错**。永远写 `override`，让编译器替你检查。

> [!warning] 运算符重载的三个陷阱
> - `&&`、`||` 重载后**失去短路特性**，不建议重载
> - `=`、`[]`、`()`、`->` 只能作**成员函数**
> - `<<`、`>>` 通常作**友元或非成员函数**（左操作数是流对象，不是你的类）
